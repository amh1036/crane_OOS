API Reference

CRANE is API-first: the Vue frontend talks to a FastAPI backend over a versioned REST API. Anything you can do in the UI, you can automate.

The OpenAPI docs are authoritative

Because the API is built with FastAPI, every running instance serves live, interactive documentation generated from the code itself. Always treat that as the source of truth for exact paths, parameters and schemas:

http://localhost:8000/docs  (Swagger UI)  ·  http://localhost:8000/redoc  (ReDoc)

Base URL

API base
http://localhost:8000/api/v1
OpenAPI schema
http://localhost:8000/openapi.json
Interactive docs
/docs (Swagger) · /redoc (ReDoc)

In production, substitute your own host and TLS-terminated domain for localhost.

Authentication

Authenticate against the API the same way the UI does — exchange credentials for a token, then send that token as a bearer credential on every subsequent request.

Authenticate & call an endpoint
# 1. obtain a token
curl -X POST http://localhost:8000/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"admin@example.com","password":"••••••••"}'

# 2. use the returned token
curl http://localhost:8000/api/v1/products \
  -H "Authorization: Bearer <token>"

Endpoint paths below are representative, to show the shape of the API. Confirm the exact routes, request bodies and response schemas against /docs on your version.

Core resources

The API mirrors the core concepts. Each resource supports the usual list / retrieve / create / update operations:

MethodPath (representative)Purpose
GET/productsList products in the registry
POST/productsRegister a new product
GET/products/{id}Retrieve a single product
GET/products/{id}/releasesList releases for a product
POST/releases/{id}/sbomUpload a CycloneDX SBOM to a release
GET/vulnerabilitiesList tracked vulnerabilities
PUT/vulnerabilities/{id}Record a VEX assessment / triage decision
GET/products/{id}/annex-iRequirement coverage map for a product
GET/audit-logRead the immutable audit trail

Conventions

  • JSON everywhere — request and response bodies are JSON; file uploads (SBOMs, reports) use multipart form data.
  • Versioned — the /api/v1 prefix lets the API evolve without breaking integrations.
  • Validated — Pydantic v2 validates every request; invalid payloads return a structured 422 describing the offending fields.
  • RBAC-enforced — your token's role determines which operations are permitted; unauthorised calls return 401/403.

Example: register a product, then list it

bash
TOKEN=$(curl -s -X POST localhost:8000/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"admin@example.com","password":"••••••••"}' | jq -r .access_token)

# create a product
curl -X POST localhost:8000/api/v1/products \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"Smart Energy Monitor","type":"device"}'

# list products
curl localhost:8000/api/v1/products -H "Authorization: Bearer $TOKEN"
