Getting Started

Installation Guide

Get CRANE running in 5 minutes. Choose your path below.

For local development/testing: Follow this guide. For production: See Configuration & Deployment for hardening, TLS, reverse proxy, backups, and LDAP setup.

Option 1: Fastest (One-Liner)

Copy and run one command. Everything else is automated.

Linux / macOS

Terminal
curl -fsSL https://raw.githubusercontent.com/cra-norm-engine/crane/main/install.sh | bash

Windows (PowerShell)

PowerShell
irm https://raw.githubusercontent.com/cra-norm-engine/crane/main/install.ps1 | iex

Done! Wait 2-5 minutes. Then open http://localhost:5173

Option 2: Manual Setup (5 Steps)

If you prefer to understand each step, follow this manual process.

Step 1: Install Docker

Linux (Ubuntu/Debian):

Terminal
sudo apt update
sudo apt install -y docker.io docker-compose-plugin
sudo systemctl start docker
sudo usermod -aG docker $USER
newgrp docker

macOS:

Download and install Docker Desktop for Mac. Start it from Applications.

Windows:

Download and install Docker Desktop for Windows. Choose WSL 2 when prompted. Restart your computer.

Verify Docker is running:

All platforms
docker run hello-world

Step 2: Clone CRANE

Linux / macOS:

Terminal
git clone https://github.com/cra-norm-engine/crane.git
cd crane

Windows:

PowerShell
git clone https://github.com/cra-norm-engine/crane.git
cd crane

Or download as ZIP:

Browser or PowerShell
https://github.com/cra-norm-engine/crane/archive/refs/heads/main.zip

Step 3: Create .env Configuration

Copy the example file:

All platforms
cp .env.example .env

Generate two random secure values:

Linux / macOS
openssl rand -hex 16  # for POSTGRES_PASSWORD
openssl rand -hex 32  # for BACKEND_SECRET_KEY
Windows PowerShell
[Convert]::ToHexString([Security.Cryptography.RandomNumberGenerator]::GetBytes(16))  # for POSTGRES_PASSWORD
[Convert]::ToHexString([Security.Cryptography.RandomNumberGenerator]::GetBytes(32))  # for BACKEND_SECRET_KEY

Edit .env and update these two lines with your generated values:

.env
POSTGRES_PASSWORD=<paste_16_byte_hex_value>
BACKEND_SECRET_KEY=<paste_32_byte_hex_value>

Step 4: Start CRANE

All platforms
docker compose up -d

First run takes 2-5 minutes while Docker builds images and downloads the vulnerability database.

Check progress:

All platforms
docker compose logs -f backend

Press Ctrl+C (Cmd+C on Mac) to stop viewing logs.

Step 5: Access CRANE

Open your browser and go to:

  • App: http://localhost:5173
  • API Docs: http://localhost:8000/docs

Default login:

Credentials
Email:    admin@example.com
Password: admin1234

Change your password on first login.

Troubleshooting

Docker is not running

Problem: Error: Cannot connect to Docker daemon

Solution:

  • Linux: Run sudo systemctl start docker
  • macOS: Open Docker.app from Applications
  • Windows: Open Docker Desktop from Start Menu

Port already in use

Problem: Error: bind: address already in use

Solution: Change the ports in .env:

.env
BACKEND_PORT=8001
FRONTEND_PORT=5174

Slow startup

Problem: Installation takes more than 5 minutes

Solution: This is normal on first run. Docker is downloading the vulnerability database (~200 MB). Check progress:

All platforms
docker compose logs backend | grep -i trivy

Can't access http://localhost:5173

Problem: Browser shows connection error

Solution: Check if containers are running:

All platforms
docker compose ps

All services should show running. If not, check logs:

All platforms
docker compose logs

Login credentials don't work

Problem: Email and password rejected

Solution: The app might still be initializing. Wait 1-2 minutes and refresh the browser. If still not working, check backend logs for errors.

Development vs. Production

This guide covers local development (your machine, localhost). For production deployment, you need additional setup.

Development (What You Just Did)

  • ✓ Running locally on your machine
  • ✓ Not exposed to the internet
  • ✓ Using default credentials
  • ✓ Testing and exploration

Production (See Configuration Guide)

  • ✗ Accessible over the internet
  • ✗ Requires TLS/HTTPS
  • ✗ Needs reverse proxy (nginx, Caddy)
  • ✗ Strong database passwords
  • ✗ Regular backups
  • ✗ LDAP/Active Directory integration (optional)

To deploy to production: Read Configuration & Deployment.
