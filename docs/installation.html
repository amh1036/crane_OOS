Getting Started

Installation & Deployment Guide

Complete walkthrough for installing CRANE in development or production, upgrading, and troubleshooting the installation process.

System Requirements

CRANE runs on any OS with Docker. Below are the official requirements:

Component Requirement Notes
Operating System Linux, macOS 11+, Windows 10/11 Any OS with Docker support
CPU Architecture amd64, arm64 Both architectures officially supported
Docker Engine ≥24.0.0 Or Docker Desktop 4.18+
Docker Compose v2 plugin Use docker compose (not docker-compose)
RAM 2 GB minimum free 4 GB+ recommended for production
Disk Space 5 GB minimum For images, database, and uploads
Network Ports 5173, 8000, 5432 free See docker-compose.yml for details

Pre-Flight Checks

Before installing CRANE, verify your system is ready:

  1. Docker is running: 
    docker info

    Should print Docker configuration without errors. On macOS/Windows, start Docker Desktop if you see "Cannot connect to Docker daemon."

  2. Compose v2 is available: 
    docker compose version

    Should print v2.x.x. If you see "no such command," upgrade Docker.

  3. Ports 5173, 8000, 5432 are available: 
    # Linux / macOS:
ss -tlnp | grep -E ':(5173|8000|5432)'

# Windows (in PowerShell):
netstat -ano | findstr /C:":5173" /C:":8000" /C:":5432"

    If ports are in use, stop the conflicting service or change the port in .env.

  4. Sufficient disk space: 
    df -h /  # Shows usage of root filesystem

    Ensure 5+ GB free space.

Understanding the Install Scripts

CRANE provides convenience install scripts for Linux/macOS and Windows. This section explains what they do, so you can audit and trust them.

What the Scripts Do

Both install.sh (bash) and install.ps1 (PowerShell) perform the same steps:

  1. Download the repository — fetches latest code as a zip from main branch on GitHub
  2. Generate secure secrets — creates .env with random 32-char keys for BACKEND_SECRET_KEY and POSTGRES_PASSWORD using openssl or the OS crypto library
  3. Start services — runs docker compose up -d to build and run containers
  4. Wait for health — polls the health endpoint for up to 120 seconds to confirm startup
  5. Print credentials — shows the default login and access URLs

Security Considerations for Scripts

Important: Never blindly pipe a remote script into bash or PowerShell. Always review it first:

Linux / macOS:

curl -fsSL https://raw.githubusercontent.com/cra-norm-engine/crane/main/install.sh -o install.sh
cat install.sh  # Review the script
bash install.sh  # Run only after reviewing

Windows (PowerShell):

irm https://raw.githubusercontent.com/cra-norm-engine/crane/main/install.ps1 -OutFile install.ps1
Get-Content install.ps1  # Review the script
.\install.ps1  # Run only after reviewing

What Permissions Do the Scripts Need?

The scripts require:

  • Execute permission on the script itself
  • Docker daemon access (user must be in the docker group on Linux, or have Docker Desktop running on macOS/Windows)
  • Write permission to the current directory and subdirectories created during clone
  • Network access to GitHub and Docker registries

Production Deployment

For production environments, use the dedicated docker-compose.prod.yml configuration, which includes hardened settings: no source code mounts, pre-built images, resource limits, and localhost-only database access.

  1. Clone the repository: 
    git clone https://github.com/cra-norm-engine/crane.git
cd crane
  2. Create and configure .env: 
    cp .env.example .env
# Edit .env and set required values:
# - POSTGRES_PASSWORD (min 32 random chars)
# - BACKEND_SECRET_KEY (min 32 random chars)
# Generate with: openssl rand -hex 32
nano .env

    Example .env (production):

    POSTGRES_DB=cra_compliance
POSTGRES_USER=postgres
POSTGRES_PASSWORD=your_strong_random_password_here
BACKEND_ENVIRONMENT=production
BACKEND_SECRET_KEY=your_strong_random_secret_key_here
BACKEND_DEBUG=false
BACKEND_CORS_ORIGINS=https://compliance.example.com
VITE_API_BASE_URL=https://compliance.example.com/api/v1
  3. Verify configuration: 
    docker compose -f docker-compose.prod.yml config

    Validates YAML syntax without starting services.

  4. Start services: 
    docker compose -f docker-compose.prod.yml up -d

    First run takes 3–5 minutes while images are pulled and the database initializes.

  5. Verify services are healthy: 
    docker compose -f docker-compose.prod.yml ps

    All services should show running.

  6. Access the app:

    Services are bound to localhost only. Access via a reverse proxy (see next section):

    • Frontend: http://localhost:5173 (via reverse proxy)
    • Backend API: http://localhost:8000/api/v1 (via reverse proxy)
    • API docs: http://localhost:8000/docs (via reverse proxy)
  7. Change default password on first login:

    Log in with admin@example.com / admin1234. You will be forced to set a new password on first login.

Reverse Proxy Setup

Never expose CRANE directly to the internet. Always run behind a reverse proxy with HTTPS/TLS. Below are examples for Nginx and Caddy.

Nginx

# Upstream to CRANE backend
upstream crane_backend {
  server localhost:8000;
}

upstream crane_frontend {
  server localhost:5173;
}

# Redirect HTTP → HTTPS
server {
  listen 80;
  server_name compliance.example.com;
  return 301 https://$server_name$request_uri;
}

# HTTPS server block
server {
  listen 443 ssl http2;
  server_name compliance.example.com;

  # TLS certificates (generate with Let's Encrypt / Certbot)
  ssl_certificate /etc/letsencrypt/live/compliance.example.com/fullchain.pem;
  ssl_certificate_key /etc/letsencrypt/live/compliance.example.com/privkey.pem;
  ssl_protocols TLSv1.2 TLSv1.3;
  ssl_ciphers HIGH:!aNULL:!MD5;

  # Frontend (Vue app)
  location / {
    proxy_pass http://crane_frontend;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }

  # Backend API
  location /api/ {
    proxy_pass http://crane_backend;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 300s;
  }

  # Redirect /docs to /api/v1/docs
  location = /docs {
    return 301 /api/v1/docs;
  }
}

Enable and test:

sudo ln -s /etc/nginx/sites-available/crane /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl restart nginx
# Get TLS cert with Certbot:
sudo certbot --nginx -d compliance.example.com

Caddy

Caddy is simpler — it auto-renews TLS certificates for you.

# Save to /etc/caddy/Caddyfile or run as: caddy run

compliance.example.com {
  # Frontend
  @frontend {
    not path /api/*
    not path /docs*
  }
  handle @frontend {
    reverse_proxy localhost:5173
  }

  # Backend API
  handle /api/* {
    reverse_proxy localhost:8000
  }

  # Redirect /docs to /api/v1/docs
  handle /docs {
    redir /api/v1/docs permanent
  }
}

Run Caddy:

caddy run

Caddy automatically obtains and renews TLS certificates from Let's Encrypt.

Upgrading CRANE

Keep CRANE updated to get security fixes and new features.

Before upgrading: Check the CHANGELOG.md for breaking changes or migration steps required.

  1. Pull the latest code / images:

    For development (docker-compose.yml):

    git pull origin main
docker compose up -d --build

    For production (docker-compose.prod.yml):

    docker compose -f docker-compose.prod.yml pull
docker compose -f docker-compose.prod.yml up -d
  2. Run database migrations: 
    docker compose -f docker-compose.prod.yml exec backend alembic upgrade head

    Always safe to run — Alembic only applies unapplied migrations.

  3. Verify health: 
    docker compose -f docker-compose.prod.yml ps
curl http://localhost:8000/api/v1/health

Rolling Back

If an upgrade breaks something, you can roll back to the previous version.

  1. Stop services: 
    docker compose -f docker-compose.prod.yml down
  2. Update to the previous version: 
    # Option A: git tag
git checkout v0.1.0  # or the previous version tag

# Option B: docker image tag (if using GHCR)
# Edit docker-compose.prod.yml: change image tag from 'latest' to 'v0.1.0'
  3. Start services: 
    docker compose -f docker-compose.prod.yml up -d
  4. Optional: rollback database migrations: 
    docker compose -f docker-compose.prod.yml exec backend alembic downgrade -1

    Only needed if the previous version requires an older schema.

Uninstalling CRANE

To remove CRANE completely:

Warning: docker compose down -v deletes the database volume and all data. Only use this if you don't need the data.

# Stop containers and remove volumes (destroys database + uploads)
docker compose -f docker-compose.prod.yml down -v

# Clean up the directory
cd ..
rm -rf crane/

If you want to preserve the database, take a backup first:

docker compose -f docker-compose.prod.yml exec postgres pg_dump -U postgres cra_compliance \
  > backup.sql

Offline / Air-Gapped Installation

For environments without internet access, you can pre-pull Docker images and transfer them offline.

  1. On a machine with internet access: 
    docker pull ghcr.io/cra-norm-engine/crane-backend:latest
docker pull ghcr.io/cra-norm-engine/crane-frontend:latest
docker pull postgres:16-alpine

# Export to tar files
docker save ghcr.io/cra-norm-engine/crane-backend:latest \
  -o crane-backend.tar
docker save ghcr.io/cra-norm-engine/crane-frontend:latest \
  -o crane-frontend.tar
docker save postgres:16-alpine -o postgres.tar
  2. Transfer the tar files to the target machine (USB drive, secure transfer, etc.)
  3. On the target machine (offline): 
    docker load -i crane-backend.tar
docker load -i crane-frontend.tar
docker load -i postgres.tar

# Verify images are loaded
docker images | grep crane
  4. Clone or copy the CRANE repository (also offline) and run: 
    docker compose -f docker-compose.prod.yml up -d

Installation Troubleshooting

Docker daemon is not running

Error: Cannot connect to Docker daemon

Solution: Start Docker. On macOS/Windows, open Docker Desktop. On Linux, run sudo systemctl start docker.

Port 5173, 8000, or 5432 is already in use

Error: bind: address already in use

Solution: Either stop the conflicting service or change the port in .env:

BACKEND_PORT=8001  # Use 8001 instead of 8000
FRONTEND_PORT=5174  # Use 5174 instead of 5173

Docker image build failed

Error: failed to build image

Solution: Check Docker is running and you have sufficient disk space. Clean up unused images:

docker system prune -a

Health check failed / service won't start

unhealthy (exit 1)

Solution: Check service logs:

docker compose logs backend  # View backend logs
docker compose logs postgres  # View database logs

First run is very slow (taking >5 minutes)

Cause: The Trivy vulnerability database is downloading on first run (~200 MB).

Solution: Wait for the database download to complete. Subsequent runs are fast. You can monitor progress:

docker compose logs backend | grep -i trivy

Can't connect to http://localhost:5173

Solution: Verify the frontend container is running and healthy:

docker compose ps frontend
docker compose logs frontend

Need more help? See FAQ & Troubleshooting for runtime issues, or open an issue on GitHub.
