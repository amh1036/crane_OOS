System Requirements

CRANE runs on any OS with Docker support. Below are the official requirements:

Component Requirement Notes
Operating System Linux, macOS 11+, Windows 10/11 Any OS with Docker support
CPU Architecture amd64, arm64 Both architectures officially supported
Docker Engine ≥24.0.0 Or Docker Desktop 4.18+
Docker Compose v2 plugin Use docker compose (not docker-compose)
RAM 2 GB minimum free 4 GB+ recommended for production
Disk Space 5 GB minimum For images, database, and uploads
Network Ports 5173, 8000, 5432 free Frontend, API, and database

Pre-Flight Checks

Before installing, verify your system is ready:

  1. Docker is running
    Terminal
    docker info

    Should print Docker configuration without errors. On macOS/Windows, start Docker Desktop if you see "Cannot connect to Docker daemon."

  2. Compose v2 is available
    Terminal
    docker compose version

    Should print v2.x.x. If you see "no such command," upgrade Docker.

  3. Ports 5173, 8000, 5432 are available
    Terminal
    # Linux / macOS:
ss -tlnp | grep -E ':(5173|8000|5432)'

# Windows (in PowerShell):
netstat -ano | findstr /C:":5173" /C:":8000" /C:":5432"

    If ports are in use, either stop the conflicting service or change the port in .env.

  4. Sufficient disk space
    Terminal
    df -h /

    Ensure 5+ GB of free space for Docker images and the database.

Development Setup

Quick setup for local testing and development using docker-compose.yml.

  1. Clone the repository
    Terminal
    git clone https://github.com/cra-norm-engine/crane.git
cd crane
  2. Generate secrets and configure .env
    Terminal
    cp .env.example .env
# Generate strong random values:
openssl rand -hex 32  # for BACKEND_SECRET_KEY
openssl rand -hex 32  # for POSTGRES_PASSWORD

# Edit .env and paste the values
nano .env

    The installer scripts handle this automatically, but for manual setup you must set BACKEND_SECRET_KEY and POSTGRES_PASSWORD.

  3. Start CRANE
    Terminal
    docker compose up -d

    First run takes 3–5 minutes while Docker builds the backend image and downloads the vulnerability database.

  4. Access the app
    Browser
    Frontend:  http://localhost:5173
API:       http://localhost:8000/api/v1
API Docs:  http://localhost:8000/docs

    Log in with admin@example.com / admin1234. You'll be prompted to set a new password on first login.

For production deployments, use docker-compose.prod.yml instead (see next section). The development compose includes volume mounts and debug mode.

Production Deployment

Deploy CRANE securely using docker-compose.prod.yml, which includes hardened settings: no source code mounts, pre-built images, resource limits, and localhost-only database access.

  1. Clone the repository
    Terminal
    git clone https://github.com/cra-norm-engine/crane.git
cd crane
  2. Generate secrets and create .env
    Terminal
    cp .env.example .env
# Generate strong random values:
openssl rand -hex 32
    .env (production example)
    POSTGRES_DB=cra_compliance
POSTGRES_USER=postgres
POSTGRES_PASSWORD=your_random_password_here
BACKEND_ENVIRONMENT=production
BACKEND_SECRET_KEY=your_random_key_here
BACKEND_DEBUG=false
BACKEND_CORS_ORIGINS=https://compliance.example.com
VITE_API_BASE_URL=https://compliance.example.com/api/v1

    Important: Set strong, random values for POSTGRES_PASSWORD and BACKEND_SECRET_KEY. Never use defaults in production.

  3. Validate configuration
    Terminal
    docker compose -f docker-compose.prod.yml config

    Validates YAML syntax without starting services.

  4. Start services
    Terminal
    docker compose -f docker-compose.prod.yml up -d

    First run takes 3–5 minutes while Docker pulls images and initializes the database.

  5. Verify services are healthy
    Terminal
    docker compose -f docker-compose.prod.yml ps

    All services should show running.

  6. Set up reverse proxy (see next section)

    Services are bound to localhost only. Access them via a reverse proxy with TLS.

  7. Change default password

    Log in with admin@example.com / admin1234. You will be forced to set a new password on first login.

Reverse Proxy & TLS Setup

Why You Need a Reverse Proxy

CRANE binds to localhost only. It's not accessible from the internet by default — which is good for security, but you need a way to expose it safely. A reverse proxy sits in front of CRANE and:

  • Forwards internet traffic to CRANE running on localhost
  • Handles HTTPS/TLS encryption so users have a secure connection
  • Protects CRANE from direct internet exposure

You need a domain name (e.g., compliance.example.com) before setting up a reverse proxy. Both Nginx and Caddy will automatically obtain TLS certificates from Let's Encrypt, but they need a valid domain to do so.

Option 1: Caddy (Recommended — Simplest)

Caddy is the easiest option — it automatically handles TLS certificates for you.

  1. Install Caddy

    Follow the Caddy installation guide for your OS.

  2. Create a Caddyfile

    Replace compliance.example.com with your actual domain.

    /etc/caddy/Caddyfile (or ~/Caddyfile)
    compliance.example.com {
  # Serve the Vue app (frontend)
  @frontend {
    not path /api/*
    not path /docs*
  }
  handle @frontend {
    reverse_proxy localhost:5173
  }

  # Route /api/* to the backend API
  handle /api/* {
    reverse_proxy localhost:8000
  }
}
  3. Run Caddy
    Terminal
    caddy run

    That's it! Caddy will:

    • Automatically request a TLS certificate from Let's Encrypt
    • Auto-renew the certificate before it expires
    • Start listening on port 443 (HTTPS)
  4. Access CRANE
    Browser
    https://compliance.example.com

    Your browser should show a valid HTTPS connection (green lock icon).

Option 2: Nginx (More Control)

Nginx requires more manual setup but gives you more control. Use this if you prefer Nginx or need specific configuration.

  1. Install Nginx and Certbot
    Terminal — Ubuntu/Debian
    sudo apt update
sudo apt install nginx certbot python3-certbot-nginx
  2. Create Nginx config

    Replace compliance.example.com with your actual domain.

    /etc/nginx/sites-available/crane
    # Redirect HTTP → HTTPS
server {
  listen 80;
  server_name compliance.example.com;
  return 301 https://$server_name$request_uri;
}

# HTTPS server block (TLS config will be added by Certbot)
server {
  listen 443 ssl http2;
  server_name compliance.example.com;

  # Forward the Vue app to the frontend container
  location / {
    proxy_pass http://localhost:5173;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }

  # Forward /api/* to the backend API
  location /api/ {
    proxy_pass http://localhost:8000;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 300s;
  }
}
  3. Enable the Nginx site
    Terminal
    sudo ln -s /etc/nginx/sites-available/crane /etc/nginx/sites-enabled/
sudo nginx -t  # Test the config syntax
sudo systemctl restart nginx

    If nginx -t shows errors, fix them before restarting.

  4. Get TLS certificates with Certbot
    Terminal
    sudo certbot --nginx -d compliance.example.com

    Certbot will:

    • Request a certificate from Let's Encrypt for your domain
    • Automatically update your Nginx config with the certificate path
    • Set up auto-renewal
  5. Verify Certbot auto-renewal
    Terminal
    sudo systemctl enable certbot.timer
sudo systemctl start certbot.timer

    This ensures your certificate auto-renews before expiration.

  6. Access CRANE
    Browser
    https://compliance.example.com

    Your browser should show a valid HTTPS connection.

Verify It's Working

Terminal
# Check if CRANE is accessible
curl https://compliance.example.com

# Check TLS certificate details
echo | openssl s_client -servername compliance.example.com -connect compliance.example.com:443 2>/dev/null | grep -A 5 "Issuer"

Troubleshooting Reverse Proxy

502 Bad Gateway error? CRANE might not be running or listening on the expected port. Check:

Terminal
docker compose -f docker-compose.prod.yml ps
docker compose -f docker-compose.prod.yml logs backend

Certbot certificate renewal failing? Test it manually:

Terminal
sudo certbot renew --dry-run

Upgrading CRANE

Keep CRANE updated to get security fixes and new features. Always check the CHANGELOG for breaking changes.

  1. Review breaking changes

    Check CHANGELOG.md for any migration steps required.

  2. Navigate to your CRANE directory

    You must run all upgrade commands inside the CRANE folder where docker-compose.yml and docker-compose.prod.yml live:

    Terminal
    cd ~/Desktop/crane  # or wherever you installed CRANE
ls -la  # verify you see docker-compose.yml, .git/, backend/, etc.
  3. Pull latest code or images

    For development (inside CRANE folder):

    Terminal
    git pull origin main
docker compose up -d --build

    For production (inside CRANE folder):

    Terminal
    docker compose -f docker-compose.prod.yml pull
docker compose -f docker-compose.prod.yml up -d

    What happens:

    • Development: `git pull` downloads code; `--build` recompiles Docker image from source
    • Production: `pull` downloads pre-built images from GitHub Container Registry
  4. Run database migrations
    Terminal
    docker compose -f docker-compose.prod.yml exec backend alembic upgrade head

    Always safe — Alembic only applies unapplied migrations.

  5. Verify services are healthy
    Terminal
    docker compose -f docker-compose.prod.yml ps
curl http://localhost:8000/api/v1/health

Rolling Back

If an upgrade breaks something, roll back to the previous version.

  1. Stop services
    Terminal
    docker compose -f docker-compose.prod.yml down
  2. Revert to the previous version

    Option A: Using git tags

    Terminal
    git checkout v0.1.0  # or your previous version tag

    Option B: Using image tags

    Edit docker-compose.prod.yml
    crane-backend:v0.1.0  # instead of latest
crane-frontend:v0.1.0
  3. Start services
    Terminal
    docker compose -f docker-compose.prod.yml up -d
  4. Optional: rollback database schema
    Terminal
    docker compose -f docker-compose.prod.yml exec backend alembic downgrade -1

    Only needed if the previous version requires an older database schema.

Uninstalling CRANE

To completely remove CRANE:

Data loss warning

docker compose down -v deletes the database volume and all data permanently. Back up first if you need the data.

Terminal
# Back up the database (optional but recommended)
docker compose -f docker-compose.prod.yml exec postgres pg_dump -U postgres cra_compliance > crane-backup.sql

# Stop and remove containers + volumes
docker compose -f docker-compose.prod.yml down -v

# Clean up the directory
cd ..
rm -rf crane/

Offline / Air-Gapped Installation

For environments without internet access, pre-pull Docker images and transfer them offline.

  1. On a machine with internet access
    Terminal
    docker pull ghcr.io/cra-norm-engine/crane-backend:latest
docker pull ghcr.io/cra-norm-engine/crane-frontend:latest
docker pull postgres:16-alpine

docker save ghcr.io/cra-norm-engine/crane-backend:latest -o crane-backend.tar
docker save ghcr.io/cra-norm-engine/crane-frontend:latest -o crane-frontend.tar
docker save postgres:16-alpine -o postgres.tar
  2. Transfer tar files to the target machine

    Use USB drive, secure transfer protocol, etc.

  3. On the target machine (offline)
    Terminal
    docker load -i crane-backend.tar
docker load -i crane-frontend.tar
docker load -i postgres.tar

docker images | grep crane
  4. Clone or copy CRANE repository and run
    Terminal
    docker compose -f docker-compose.prod.yml up -d

Understanding the Install Scripts

CRANE provides convenience installer scripts (install.sh and install.ps1) that automate the clone-and-setup process. This section explains what they do, so you can audit and trust them.

What the Scripts Do

install.sh / install.ps1
1. Download the repository (as a zip from main branch)
2. Generate secure secrets (BACKEND_SECRET_KEY, POSTGRES_PASSWORD)
3. Create .env with the generated secrets
4. Run: docker compose up -d
5. Poll the health endpoint for up to 120 seconds
6. Print the default credentials and access URLs

Safe Script Execution

Always review scripts before executing. Never blindly pipe remote scripts into bash or PowerShell.

Linux / macOS:

Terminal
curl -fsSL https://raw.githubusercontent.com/cra-norm-engine/crane/main/install.sh -o install.sh
cat install.sh  # Review the script
bash install.sh  # Run only after reviewing

Windows (PowerShell):

Terminal
irm https://raw.githubusercontent.com/cra-norm-engine/crane/main/install.ps1 -OutFile install.ps1
Get-Content install.ps1  # Review the script
.\install.ps1  # Run only after reviewing

Script Permissions

The scripts require:

  • Execute permission on the script itself
  • Docker daemon access (docker group on Linux; Docker Desktop on macOS/Windows)
  • Write permission to the installation directory
  • Network access to GitHub and Docker registries

Installation Troubleshooting

Docker daemon is not running

Error: Cannot connect to Docker daemon

Solution: Start Docker. On macOS/Windows, open Docker Desktop. On Linux, run sudo systemctl start docker.

Port 5173, 8000, or 5432 is already in use

Error: bind: address already in use

Solution: Change the port in .env:

.env
BACKEND_PORT=8001  # Use 8001 instead of 8000
FRONTEND_PORT=5174  # Use 5174 instead of 5173

Docker image build failed

Error: failed to build image

Solution: Verify Docker is running and you have 5+ GB of disk space. Clean up old images:

Terminal
docker system prune -a

Health check failed / service won't start

unhealthy (exit 1)

Solution: Check the service logs:

Terminal
docker compose logs backend
docker compose logs postgres

First run is very slow (>5 minutes)

The Trivy vulnerability database is downloading on first run (~200 MB). Subsequent runs are fast.

Solution: Wait for the database to download. Monitor progress:

Terminal
docker compose logs backend | grep -i trivy

Can't connect to http://localhost:5173

Frontend not responding

Solution: Verify the frontend container is healthy:

Terminal
docker compose ps frontend
docker compose logs frontend
