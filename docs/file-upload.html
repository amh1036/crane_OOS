File Upload & Management

CRANE allows teams to upload and attach evidence documents throughout the compliance lifecycle: SBOMs, risk assessments, pentests, security reports, and more. This guide covers upload capabilities, storage, limits, and best practices.

Supported File Types

CRANE supports uploads in these categories:

SBOM Documents

  • CycloneDX (.json, .xml) — NTIA-compliant component manifests
  • SPDX (.json, .rdf, .tv) — Standard Package Data Exchange format
  • Analyzed for: completeness, component count, license coverage, CVE matches

Evidence & Compliance Documents

  • Risk Assessments (.pdf, .docx) — STRIDE, TARA, or custom methodology documentation
  • Penetration Test Reports (.pdf) — Third-party security assessment results
  • Architecture Diagrams (.pdf, .png) — System design and data flow
  • Threat Models (.pdf, .xlsx) — Risk matrices and mitigation tracking
  • Incident Reports (.pdf, .docx) — Security incident documentation
  • Audit Logs & Evidence (.csv, .xlsx) — System logs, deployment records

Configuration & Policy Documents

  • CVD Policy (.pdf, .txt) — Coordinated Vulnerability Disclosure policy
  • Security Policy (.pdf, .docx) — Product security statement
  • Support Lifecycle (.xlsx) — Release support periods and EOL dates

Not seeing a file type you need? CRANE also accepts generic document uploads (.pdf, .docx, .pptx, .txt) attached to any product, release, or assessment for ad-hoc evidence linking.

Storage & Limits

Storage Location

Uploaded files are stored in the backend container at:

Path
/workspace/backend/uploads/

For Docker deployments, this path can be mapped to persistent storage:

docker-compose.prod.yml
backend:
  volumes:
    - crane_uploads:/workspace/backend/uploads
volumes:
  crane_uploads:
    driver: local

File Size Limits

Default limits (configurable):

  • Single file: 500 MB (e.g., large SBOM database exports)
  • Per release: No hard limit, but recommended <2 GB total
  • Per product: Unlimited (but consider storage capacity)

To adjust limits, set in .env:

.env
BACKEND_MAX_UPLOAD_SIZE_MB=1000  # Increase single file limit to 1 GB

Disk Usage Planning

Estimate storage needs:

  • Small deployment (<50 products): 10-20 GB sufficient
  • Medium (50-500 products): 50-100 GB recommended
  • Large (>500 products): 200+ GB; plan for growth

Monitor upload volume:

Terminal
du -sh /workspace/backend/uploads/  # Check total upload disk usage

Security & Data Retention

Access Control

File access is tied to product-level permissions:

  • Only users with read access to a product can view its attachments
  • Only users with edit access can upload or delete files
  • Audit log records all file uploads and downloads with timestamps and user IDs

Encryption at Rest

Files are stored unencrypted on the filesystem by default. For sensitive compliance data, consider:

  • Full-disk encryption (host OS level, LUKS, BitLocker)
  • Container storage encryption (Docker secrets, encrypted volumes)
  • Cloud storage (AWS S3 with encryption, Azure Blob Storage with TDE)

Data Retention Policy

Files are kept indefinitely by default. Implement retention policies to manage storage:

Cleanup old uploads (cron job)
#!/bin/bash
# Delete files not accessed in 2 years
find /workspace/backend/uploads -atime +730 -delete

Alternatively, export compliance packages periodically and archive them to cold storage (S3 Glacier, Azure Archive).

SBOM Processing

Upload & Analysis

When you upload an SBOM:

  1. CRANE parses the document

    Extracts components, versions, licenses, and vulnerability data.

  2. Quality scoring

    Evaluates completeness (% of components with versions, licenses, hashes).

  3. CRA validation

    Checks compliance against NTIA minimum elements and CRA Annex I requirements.

  4. CVE cross-reference

    Matches components against OSV and NVD databases to flag known vulnerabilities.

  5. Diff against previous

    Highlights new/changed/removed components compared to the last release's SBOM.

SBOM Management

You can upload multiple SBOMs per release (e.g., firmware + dependencies). CRANE tracks:

  • Upload date and user
  • File size and format (CycloneDX vs SPDX)
  • Quality score and CRA compliance status
  • Associated vulnerabilities and their EPSS scores

To diff two SBOMs: Upload the new SBOM and CRANE automatically compares it to the previous version, showing:

  • New components added
  • Versions upgraded or downgraded
  • Components removed (end-of-life dependencies)
  • License changes

Risk Assessment & Evidence Attachments

Linking Evidence to Assessments

For each risk assessment or release gate:

  • Attach the assessment document (PDF of the STRIDE model, Excel threat matrix, etc.)
  • Attach approval sign-off (email, scanned form, PDF signature)
  • Attach remediation evidence (CVE patch logs, security update proof)
  • Attach pentesting report (external or internal security assessment)

Files are versioned — you can upload a new assessment document and the old one remains in the history for audit purposes.

Audit Trail

Every file action is logged:

  • Who uploaded the file (user ID)
  • When (timestamp to the second)
  • What type (SBOM, risk assessment, pentest, etc.)
  • File name and size
  • Who accessed/downloaded it and when

Exporting & Sharing Files

Download Individual Files

Click "Download" on any file attachment in CRANE to retrieve it. All downloads are logged.

Export Full Compliance Package

CRANE offers a "full export" feature that packages all product data + attachments:

  1. Navigate to Product → Export

    Select what to include: product metadata, releases, SBOMs, risk assessments, audit log.

  2. Download ZIP

    CRANE generates a ZIP containing JSON/CSV + all attachments in a folder structure.

  3. Use for Notified Body

    Share the complete package with auditors, regulators, or customers. All evidence is together.

Troubleshooting File Issues

Upload fails with "file too large"

Solution: Increase the limit in .env:

.env
BACKEND_MAX_UPLOAD_SIZE_MB=2000

Then restart the backend.

Disk space running out

Solution: Archive old uploads and remove them from the live filesystem:

Terminal
tar -czf /archive/uploads-2025.tar.gz /workspace/backend/uploads/
rm -rf /workspace/backend/uploads/*  # Only after backup!

SBOM upload succeeds but shows "invalid CycloneDX"

Solution: Validate the SBOM format:

  • Use CycloneDX schema validator to check XML/JSON
  • Ensure it includes the required `` section
  • Check that component versions are strings, not numbers
